# AgroESEP

Мобильное приложение проекта Института математики НАН КР
«Экономико-математические методы оптимизации производственного
и ресурсного потенциала хозяйств различных форм».

Пользователь вводит данные своего хозяйства (угодья, план производства,
породы) — приложение решает задачу линейного программирования
(симплекс + метод ветвей и границ) прямо на устройстве и предлагает
оптимальный план с наименьшими затратами.

- Два языка интерфейса: кыргызский и русский (переключатель в аппбаре).
- Работает без интернета: расчёт локальный, история — в Hive.

## Математическая модель

Постановка института — формулы (1.1)–(1.6), они показаны в приложении
на экране «Модель». Нумерация сохранена, чтобы формулы на экране
совпадали с документом.

К ним добавлены три расширения под условия Кыргызстана:

| Что | Где в модели | Зачем |
|---|---|---|
| Пастбища как источник корма | культура «пастбищный корм» на угодье `pasture` | около 85 % сельхозугодий республики — пастбища; раньше введённая площадь пастбищ не влияла на ответ вообще |
| Закупка кормов `z[j]` | слагаемое в (1.1), слагаемое в (1.3), новая (1.8) | нехватка пашни больше не даёт отказ «решение не найдено»: модель сравнивает стоимость гектара с ценой корма на рынке |
| Предел поголовья `n[l]` | новая (1.7) | без верхней границы оптимум линейной задачи угловой, и всё стадо встаёт на одну породу |

Порядок переменных в задаче — `x[k][j]`, затем `y[h][l]`, затем `z[j]`.
Закупка приписана в хвост намеренно: индексы `x` и `y` не сдвинулись,
и контрольные примеры прежней версии сверяются с новой как есть.

## Архитектура

Clean Architecture (feature-first) + BLoC (кубиты из `flutter_bloc`).

```
lib/
├── main.dart                  # composition root: сборка зависимостей
├── core/                      # сквозное: тема, локализация, роутер, форматирование
│   ├── l10n/                  # .arb-файлы (ky/ru) и сгенерированные классы
│   ├── router/                # go_router: маршруты и нижняя навигация
│   └── theme/
├── data/                      # общий data-слой (используется несколькими фичами)
│   ├── models/                # сущности: OptimizationInput/Result, CalculationRecord
│   ├── local/                 # CalculationStore (Hive / in-memory)
│   ├── normatives/            # нормативы института + импорт из Excel
│   └── remote/                # контракт FarmSolver + HTTP-реализация
├── solver/                    # локальный решатель: симплекс, ветви и границы
└── features/
    ├── settings/
    │   ├── domain/            # SettingsRepository (контракт)
    │   ├── data/              # HiveSettingsRepository
    │   └── presentation/      # LocaleCubit (язык интерфейса)
    ├── calculator/
    │   ├── domain/            # FarmType, CalculationPhase, PlausibilityWarning
    │   └── presentation/      # CalculatorCubit + CalculatorState, мастер, результат
    ├── history/
    │   ├── domain/            # CalculationDiff — сравнение двух расчётов
    │   └── presentation/      # история, сравнение
    ├── info/presentation/     # главная, «о проекте», модель, контакты
    └── admin/presentation/    # импорт нормативов (для сотрудников института)
```

Правила зависимостей:

- **presentation** (экраны + кубиты) зависит от **domain** и получает
  реализации data-слоя через конструктор — экраны не знают ни о Hive,
  ни о деталях хранилища.
- **domain** — чистые Dart-классы и контракты (`abstract interface`),
  без Flutter- и внешних зависимостей.
- **data** — реализации контрактов (Hive, HTTP).
- Все зависимости собираются в одном месте — `main.dart`
  (composition root). У каждого контракта есть реализация-заглушка
  (in-memory), поэтому тесты работают без моков и флагов.

Состояние — кубиты:

| Кубит | Состояние | Отвечает за |
|---|---|---|
| `CalculatorCubit` | `CalculatorState` (иммутабельный, copyWith) | мастер ввода, запуск расчёта, история записей |
| `LocaleCubit` | `Locale` | язык интерфейса, сохранение выбора |

Экраны подписываются через `BlocBuilder`/`BlocListener`.
