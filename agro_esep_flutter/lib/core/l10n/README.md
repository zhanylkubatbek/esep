# Локализация

`app_ru.arb` — источник ключей (русский, базовый язык), 261 ключ.
`app_ky.arb` — кыргызский, переведён полностью.

## Состояние перевода

Обе локали (`ru`, `ky`) включены в `supportedLocales`. Язык переключается
кнопкой «КЫР | РУС» в аппбаре главного экрана; выбор сохраняется на
устройстве (`LocaleController`, Hive-бокс `settings`, ключ `locale`).

**Кыргызский перевод — предварительный.** Сельхозтерминологию
(«тукум», «жерлер», «тоют балансы» и т.д.) должен подтвердить институт;
после сверки достаточно поправить значения в `app_ky.arb` и выполнить
`flutter gen-l10n`.

Длинные тексты проекта (описание, цели, задачи, шаги калькулятора) живут
не в .arb, а в `data/project_content.dart`: там два набора
(`ProjectContent.ru` / `ProjectContent.ky`), выбор — `ProjectContent.of(context)`.

## Что осталось зашитым в коде — и почему

Весь интерфейс переведён, включая экран администратора, PDF-отчёт и
экран «Модель». Зашитыми остаются только строки, которые переводить
нельзя:

| Файл | Строки | Почему |
|---|---|---|
| `data/normatives/excel_import.dart` | `Угодья`, `Культуры`, `Продукция`, `Породы`, `Версия` | Имена листов, по которым лист ищется в .xlsx. Это ключи формата файла, а не подписи; перевод сломал бы импорт. Экран администратора показывает их через те же константы. |
| `data/normatives/excel_import.dart` | `т/год` | Единица по умолчанию, если в файле не заполнен столбец. Это значение данных, оно уезжает в нормативы. |
| `features/info/home_screen.dart` | `КЫР`, `РУС` | Переключатель языка: каждая подпись на своём языке. |
| `features/info/contacts_screen.dart` | адрес, телефон, почта | Фактические данные из футера сайта института. |

## Названия из нормативной базы

Культуры, угодья, породы и продукция приходят не из .arb, а из
`assets/normatives/normatives.json`. База двуязычная: рядом с `name`
лежит необязательное `name_ky` (у продукции ещё `unit_ky`, у пород —
`breed_name_ky` и `product_name_ky`).

Экраны берут названия через `normatives.namesFor(L.of(context).localeName)`
— он отдаёт `NormativeNames` с методами `land`, `crop`, `product`,
`breed`, `unit`. Если кыргызского названия нет, возвращается русское;
если id вообще незнаком (расчёт сохранён на другой версии базы) —
сам id. Сами записи (`Crop`, `BreedProduct`) перевода не хранят: они
уходят в запрос решателю и в сохранённый расчёт, где название — лишний
вес, а идентификатор от языка не зависит.

Кыргызские названия в демонстрационной базе предварительные —
подтверждает институт. Полноту стережёт `test/normative_names_test.dart`.

**Импорт из Excel кыргызских названий пока не переносит:** у листов
фиксированный порядок столбцов, и куда класть перевод — решать вместе
с институтом. Загруженная база будет показывать русские названия
на обоих языках.

PDF-отчёт печатается на языке, выбранном в приложении: `PdfReport`
получает `L` и `ProjectContent` от экрана, который его открывает.

## Как править перевод

1. Изменить значения в `app_ky.arb` (ключи не трогать; метаданные
   `@ключ` с `placeholders` живут только в шаблоне `app_ru.arb`).
2. `flutter gen-l10n` — классы перегенерируются.
   Полноту перевода стережёт `test/l10n_test.dart`: набор ключей
   в обоих файлах обязан совпадать.
3. Длинные тексты — в `data/project_content.dart` (`ProjectContent.ky`).

## Важно про идентификаторы

В сохранённых расчётах хранится **идентификатор** типа хозяйства
(`FarmType.name`, например `peasant`), а не переведённое название: строка
перевода как ключ ломалась бы при смене языка. Для отображения название
берётся через `FarmType.title(L.of(context))`.
